# AI 会话留存边界

状态：说明文档，随 VOXWARD-SUB-016 提交。每一项都标明「已实现」「部署要求」「待实测」或「未验证」。

适用范围：一次性 AI 会话（提案 §8.1、§8.4）在应用侧产生的文件，以及 Kiro CLI 与模型提供方可能保留的数据。

## 1. 应用侧保存什么

| 对象 | 位置 | 保留期限 | 删除方式 | 状态 |
| --- | --- | --- | --- | --- |
| 运行目录（标记文件） | `KIRO_RUNTIME_ROOT/run-*/.voxward-session` | 只在一次运行期间存在 | 每批结束时删除。异常残留由启动时的孤儿扫描删除。 | 已实现（`lifecycle.test.ts`、`orphan-sweep.test.ts`） |
| 元数据记录 `session.json` | 同上 | 同上 | 随目录删除 | 已实现。只含批次 ID、状态、时间戳、进程 ID、Kiro 会话 ID。不含正文、itemId 映射、stdout。 |
| 模型输入与输出正文 | 只在 stdin 管道与进程内存中出现，不写盘 | 进程内存期间 | 运行结束即释放 | 已实现（`keeps only a marker and a metadata record`） |
| stderr | 只计数，不保存，不回显 | — | — | 已实现（`never echoes stderr`） |
| 错误信息 | 只带错误码与退出码 | — | — | 已实现（`RUN_FAILED` 测试） |

本表不涉及业务日志。校验后的分类结果进入 Technical Log 或 Change Log 时，遵循那些日志的保留与删除期限（提案 §8.4、§12.3），不在本适配器内处理。

## 3. 结果的含义

- 会话删除结果为 `DELETE_REQUESTED` 时，只表示 CLI 以退出码 0 接受了删除命令。
- 它不表示提供方已经删除数据。
- Archive、导出，或移入可恢复的回收区，都不等于删除（提案 §8.4）。
- 应用侧删除运行目录不等于提供方删除。两者分别记录，不互相代替。
