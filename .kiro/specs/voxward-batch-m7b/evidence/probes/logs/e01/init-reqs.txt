VW-R-001@1: 远端自托管 Middleware：模块化单体、浏览器多人协作、频道评分、审核/精翻、人工处理和受控输出。采用 pnpm、TypeScript、Fastify、SQLite WAL、Drizzle、React、Vite；按 proposal 第 9 节的九个版本化模块契约解耦。
VW-R-002@1: 首期真实输入来自 YouTube 官方 streamList，处理去重、重连补发、结束、配额和凭据失效；区分 API key/OAuth 能力和责任。身份按真实平台字段/来源映射，unknown 不冒充已验证订阅关系。
VW-R-003@1: 基础检查覆盖昵称、正文和组合，包含精确、归一化、读音/转写及有界正则。白名单与噪声也先检查；普通消息选择性 AI，付费自定义文本始终安全审核，例外先入队列。下游统一 ALLOW/BLOCK。
VW-R-004@1: 频道评分为核心，按平台+主播频道+主体隔离。服务端负责钳制、actualDelta、冷却、多规则最大扣分、幂等结算和身份变化；noise 不变，故障不扣分；分值不公开、不跨频道共享。
VW-R-005@1: 昵称缓存按主体/昵称哈希/规则版本/期限失效，安全称呼和读音优先本地。后台仅复盘 UNSETTLED_FAST_PASS，排除已结算/人工/例外/删除/过期对象；跨条临时别名不跨任务复用，候选词须人工确认。
VW-R-006@1: 推理并发按服务限流和宿主资源动态约束，不固定两个子代理；微批、大小、容量和等待均有界，付费优先、复盘让出实时容量、删除优先失效旧任务。有限保序、投递 ID/状态及有效期保证实时可用性。
VW-R-007@1: 人工裁决、名单和词条操作可用；版本/任务 ID/处理代次及事务防止晚到覆盖和重复结算，纠分依据真实账本。提供可选“拒绝并从平台删除”，平台写权限/配额及状态独立于本地拦截。
VW-R-008@1: 普通审核、SC 和复盘分别使用版本化 JSON 契约；校验字段/枚举/长度、批内 ID 完整唯一性、Unicode 区间与理由一致性，初版整批受控失败。SC 精翻可关而安全审核不可关，译文/梗注/答谢提示也检查。
VW-R-009@1: AI 会话一次性，只传必要文本、规则、临时 itemId/任务内别名，不默认传平台 ID、昵称/账本/凭据。不长期保存完整对话、提示实例和工具轨迹；成功/失败/取消及异常恢复清理本地与 Crew 内容残留。
VW-R-010@1: Kiro CLI/Crew 是实际 MVP 推理/协调选型，业务权威留在服务端。用户分别选择实时、SC 和复盘模型，适配器声明真实能力；高级快速模型及 reasoning 建议依据实测，未来替换不改核心业务。
VW-R-011@1: SQLite WAL 在服务器本地持久卷，单后端短事务统一写入，多浏览器并行读取。裁决、账本与投递意图一致；网络/模型不占长事务。正文、临时映射和验证 JSON 集中于受控 Technical Log，队列/Crew 不重复存正文。
VW-R-012@1: 实施部署管理员、频道所有者、房管、单独授权数据管理员和只读下游角色。服务端对 HTTP/WebSocket/批量/任务及日志字段逐次鉴权；HTTPS/WSS、CSRF、文本转义、可撤销输出凭据和独立最小权限业务 agent 覆盖真实边界。
VW-R-013@1: 数据面板提供请求受理/核验/执行/结果，以及“仅删除数据”和“删除并加入记分例外名单”。组合操作在事务内先确认偏好、失效旧任务并登记删除，再清理；重试幂等，部分失败与外部不可控范围明确。
VW-R-014@1: 记分例外是频道独立偏好：所有消息先入审核，基础明确拒绝可结束，其余 AI/人工，不走白名单/噪声/高分快通道。身份、实时、复盘和人工均不能记分，不隐藏旧分；恢复需明确请求，仅保留必要偏好标记。
