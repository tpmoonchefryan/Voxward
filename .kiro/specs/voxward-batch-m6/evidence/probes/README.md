# 第 m6 批（总表第 6 批：S010、S011、S014）验收探针与原始输出

- 运行方式见 acceptance.md 的「0. 执行记录」。探针只按绝对路径导入检出内的源码与测试夹具，用 `apps/server/node_modules/.bin/tsx` 运行；工作目录要有软链接 `<work>/node_modules/@voxward/contracts` → `<检出>/packages/contracts`。脚本只统计，不以失败退出，看末尾的 `checks N, failures M`。每条 `OK`/`FAIL` 行写的是它检查的契约，`FAIL` 表示候选不满足；`NOTE` 只记录观察。数据全部是合成的。
- 对照副本：`git -C <检出> archive 40223e2 apps/server/src apps/server/test docs/data-dictionary.md | tar -x -C <work>/old/40223e2`，再 `ln -s <检出>/apps/server/node_modules <work>/old/40223e2/apps/server/node_modules`（契约包用检出版本；本批契约改动对旧代码在运行时用到的导出是增量）。把 `<work>/old/40223e2` 当作 `<检出>` 传入。
- `probe-m6-s010.mts <检出> <label> [all|parse]`（E50）：§A 按官方 liveChatMessage 资源形状给出文字、带留言与不带留言的 Super Chat、会员里程碑、Super Sticker，经 `parseStreamItem` 与 `toBusinessEvent` 看事件正文（Q40、G10）；§B `validateScBatch` 的生成文本命中（Q23）；§C 精翻开的流水线（跨语种、BLOCK 与命中逐条扣、来源标识、本地称呼、无规则端口时整批拒绝）；§D 精翻关经真实 S008 适配器与假 CLI；§E 模型设置与能力报告；§F 所选模型是否到达精翻关的安全审核（读假 CLI 的 argv）。对照副本只跑 `parse`（§A、§B）。
- `probe-m6-s011.mts <检出> <scratch> <label>`（E60）：§A 车道与共用协调器（复盘运行器与 S009 Crew 执行器都接同一个协调器）；§B 任务内别名；§C 统一结算（真实计分引擎与迁移后的 SQLite 计分端口）；§D Q27 前半；§E Q38 记录窗口；§F 候选词卡片（真实角色矩阵 `capabilitiesOfMembership`）；§G 复盘输出的整批契约（与 inference-provider 的 `validateReviewBatch` 对同一输出的结论并列）。
- `probe-m6-s011-heap.mts <检出> <work> <label>`（E61）：要加 `NODE_OPTIONS=--expose-gc`。三组各 20 条复盘任务（因删除被取消、在协调器里到期、经 runBatch 结算），正文带唯一标记；删掉存储行后写堆快照到 `<work>/logs/probes/`，按标记计数后删除快照。模型替身不记录输入，避免探针自己持有正文。
- `probe-m6-s014.mts <检出> <scratch> <label> [all|ledger]`（E70）与 `probe-m6-s014-race-child.mts`：在 `<scratch>` 下建临时目录并迁移真实 SQLite，结束后删除。§L 计分端口（Q19①②、Q21，对照副本只跑这一节）；§A 人工接管、晚到 AI、第二个任务、代次与版本守卫；§B 六个子进程在同一库文件上同时提交同一任务；§C 改判纠分（含后续条目触底的观察）；§D 改判旧消息与投递；§E 显式补发；§F 名单与词条权限、Change Log；§G Q19③ 同一事务；§H 例外主体经 DecisionService；§M 迁移 0005 与数据字典。
- S009 回归（E30–E34）：`probe-s009.mts`、`probe-s009-extra.mts`、`probe-s009-order.mts`、`probe-s009-b6.mts` 是第 6 批 `.kiro/specs/voxward-batch6/evidence/probes/` 的原样副本（sha256 见 `logs/s009/probe-sha.txt`），参数同第 6 批；E30、E34 要加 `NODE_OPTIONS=--expose-gc`。
- `net/preload.mjs` 经 `NODE_OPTIONS=--import` 加载：非回环连接、DNS 与 fetch 一律拒绝；`PROBE_DENY_PORTS` 列出的本机端口（运行前已在监听的端口，见 `logs/e08/deny-ports.txt`）即使走回环也拒绝。`net/selfcheck.mjs` 是它的自检。`shim/` 放在 PATH 最前，替换 `kiro-cli`、`kirocrew`、`kiro`，每次调用都记录并以 97 退出。三者沿用第 6 批。
- `out-src/` 是生成 acceptance.md 与 evidence-records.json 的片段与脚本：`node out-src/build-out.mjs <out>`，读取同目录的 `cards-m6.json`（E01 读到的 9 单实时验收行）、`rows.mjs`（每行判定与依据）与 `acc-*.md`。脚本做格式自检，有问题时退出 1 且不写文件。
- `logs/`：`gates/` 为 E02–E06，`e07/` 为冒烟，`e08/` 为拦截下的全量测试与拦截记录，`e09/` 为负面对照，`e10/` 为三份 spec check，`e11/` 为静态核对，`s009/` 为 E30–E34，`probes/` 为 E50、E60、E61、E70 在候选与对照上的输出。
